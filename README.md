# متصفح آمن — Secure Browser (الإصدار الإنتاجي 1.8.0)

متصفح Android احترافي **قابل للاستخدام اليومي** مبني على **Chromium (System WebView)** مع:

- **قائمة بيضاء مفعّلة دائمًا** — لا يمكن إيقافها من أي إعداد أو مسار.
- **طبقة أمان مركزية (fail-closed)** — كل تنقل/تنزيل/تطبيق خارجي يمر عبرها.
- **لوحة والدين كاملة** محمية برمز (PBKDF2 + حماية brute force + قفل تلقائي).
- **وصول مؤقت** بنافذة زمنية (5/10/15/30/60/مخصص) يعود بعدها فرض القائمة تلقائيًا.
- **مدير تنزيلات حقيقي** بتقدم/سرعة/إيقاف/استئناف/موافقات وسياسة أنواع ملفات.
- **تطبيقات خارجية** (Telegram/WhatsApp/YouTube/Maps/Mail/Phone/SMS) عبر بوابة سياسة.
- **تاريخ + نشاط محظور + خط زمني موحّد** — حماية السجل من المستخدم العادي.
- تبويبات بمعاينات + استعادة جلسة + بحث داخل الصفحة + ملء شاشة غامر + تكبير + مشاركة + رفع ملفات.
- عربي/إنجليزي + RTL/LTR + Dark Mode + شاشات حظر وخطأ أصلية.

**سجل التغييرات 1.9.0 (ثلاث ميزات جديدة بطلب صريح: قارئ QR مدمج + روابط الشبكة المحلية + نسخ احتياطي شامل):**

- **قارئ رموز QR مدمج (روابط المواقع ونصوص البحث):**
  (أ) زر QR في شريط العنوان + عنصر في قائمة المتصفح — شاشة مسح احترافية
  بإطار مستدير وأركان مميزة وخط ليزر متحرك وفلاش للتصوير الليلي.
  (ب) التقنية: CameraX (معاينة + تحليل حي) + ZXing للفك (QR_CODE +
  DATA_MATRIX + AZTEC) — فك إطار YUV مع تصحيح دوران الجهاز واقتصاص
  نافذة الإطار المرئية فقط (أسرع وأدق)، بمهلة بين المحاولات للبطارية.
  (ج) **المسح لا يتجاوز أي حماية**: نتيجة الرمز تدخل نفس مسار شريط العنوان
  حرفيًا (resolveInput → SecurityEngine) — الرابط يخضع للقائمة البيضاء
  والشبكة المحلية كأي كتابة يدوية، والنص يذهب لمحرك البحث المُعدّ.
  (د) تنظيف المحارف الصفرية العرض/توجيه النص من الرموز المولدة + حوار
  نتيجة بمعاينة وختيارات (فتح/بحث/نسخ/متابعة المسح) + اهتزاز حسّي.
  (هـ) صلاحية الكاميرا وقت التشغيل مع شاشة تفسير واضحة — الكاميرا للمسح
  فقط، لا تصوير ولا تخزين أي إطار.
- **روابط الشبكة المحلية تعمل دون قائمة بيضاء:**
  (أ) سياسة LocalNetworkPolicy خالصة وقابلة للاختبار: نطاقات IPv4 الخاصة
  (10/8، 172.16/12، 192.168/16، 127/8، 169.254/16، 100.64/10، 0/8)،
  صيغ IPv4 غير القياسية التي يطبّعها Chromium (127.1، 0x7f000001،
  0177.0.0.1، 3232235521…)، IPv6 (::1، ::، fe80::/10، fc00::/7،
  ::ffff: مدمج IPv4)، وأسماء المضيفين المحلية (localhost، *.localhost،
  *.local mDNS، *.home.arpa RFC 8375، *.lan، *.internal).
  (ب) **لا DNS resolution في كشف المحلية** — اسم نطاق عام يُوجّه لـ IP
  خاص (DNS rebinding) لا يمر هنا إطلاقًا فيبقى خاضعًا للقائمة البيضاء.
  (ج) بطاقة تحكم للوالد في إعدادات الوالدين (الافتراضي: مفعّل) — الإيقاف
  يعيد الحكم لهذه الروابط للقائمة البيضاء كالمعتاد. المخططات الخطرة
  و userinfo تظل محظورة حتى على العناوين المحلية.
- **نسخ احتياطي واستعادة شاملة لكل بيانات المتصفح:**
  (أ) تصدير JSON موقّع ببصمة SHA-256: القائمة البيضاء كاملة + سجل
  التصفح + سجل التنزيلات + النشاط المحظور + كل الإعدادات — عبر SAF
  (CreateDocument) بلا أي صلاحيات تخزين، واسم ملف مؤرّخ تلقائيًا.
  (ب) استيراد بفحص هيكلي fail-closed (format/version/checksum) مع حوار
  ملخص قبل التطبيق ووضعا **دمج** (تخطي المكرر من القائمة البيضاء) أو
  **استبدال** (مع تحذير صريح) — كل العملية داخل معاملة Room واحدة.
  (ج) تخطي العناصر التالفة فرديًا مع تقرير نتيجة دقيق (+أعداد/تخطّيات)،
  ومفتاح policy_schema لا يعبر النسخة إطلاقًا (ترحيل السياسة ملك
  للتطبيق وحده).
  (د) رمز الوالدين اختياري في التصدير (هاش PBKDF2 فقط — لا نص صريح
  أبدًا) بخانة تأكيد صريحة، واستعادته بخانة مستقلة بعد تحقق صارم.
- اختبارات جديدة: LocalNetworkPolicyTest (كل النطاقات وصيغ radix
  المختلفة وIPv6 وأسماء المضيفين وسيناريو rebinding)،
  SecurityEngineLocalNetworkTest (السماح دون قواعد + بوابة الوالد +
  بقاء المخططات الخطرة و userinfo محظورة فوق العناوين المحلية)،
  QrResultPolicyTest (روابط/بحث/تنظيف المحارف المخفية)،
  BackupCodecTest (دورة كاملة + فساد البصمة + التخطي الفردي +
  policy_schema + قسم الرمز).

**سجل التغييرات 1.8.0 (إصلاحان من الاستخدام الفعلي: فتح مشغلات الفيديو الخارجية + إيماءة الحواف):**

- **مشغل زن وكل مشغلات الفيديو — «افتح في برنامج التشغيل» يعمل الآن:**
  (أ) **الجذر**: كانت سياسة intent:// تسمح فقط بمشغلات قائمة مغلقة (VLC/MX/KM/…)
  — مشغلات المنصات التعليمية الخاصة (Zen Player وغيرها) كانت تُحظر فشل-مغلق،
  وفي مسار الإطارات الفرعية (تقنية الإطلاق المخفية) كان الحظر **صامتًا تمامًا**
  فلا يحدث شيء عند الضغط.
  (ب) **سياسة v1.8.0 — وجهة معلنة = بوابة التطبيقات الخارجية**: أي intent مثبّت
  بحزمة (`package=`) يُفتح عبر نفس بوابة المخططات المخصصة (external_apps +
  تأكيد نظامي) — إيقاف عدم الاتساق القديم: `zenplayer://` كانت تمر منذ v1.4.0
  بينما `intent://…;package=<نفس التطبيق>` يُحظر دون فائدة أمنية.
  (ج) **كشف وسائطي أوسع**: المخطط الداخلي (scheme=vlc/rtsp/mxplayer/…)
  يُعتبر وسائطيًا حتى مع حزمة مجهولة — يمر عبر بوابة «مشغلات الفيديو».
  (د) **تحصين intent redirection**: تجريد `component=`/`selector=` من كل intent
  محلل — الوجهة تُحسم بالحزمة والفعل والبيانات فقط (أفضل ممارسات جوجل).
  (هـ) **رابط احتياطي كالكروم**: عند عدم وجود التطبيق المستهدف يعرض حوار
  «لا يوجد تطبيق» زر «فتح الرابط في المتصفح» لـ S.browser_fallback_url —
  بشرط مروره بالقائمة البيضاء (يمر بأمان كأي تنقل داخلي).
- **السحب الجانبي للرجوع/التقدم — يعمل الآن على كل الأجهزة:**
  (أ) **الجذر على Android 10+**: إيماءة النظام الجانبية كانت تستحوذ على السحب
  من الحواف قبل وصوله للتطبيق (ACTION_CANCEL) — لذا عمل السحب الرأسي
  (للتحديث) بامتياز بينما لم يعمل الجانبي إطلاقًا. الحل: حجز شرائط الحواف
  اليسرى/اليمنى من إيماءة النظام عبر systemGestureExclusionRects
  (32dp × 200dp مركزية — الحد الذي يكرمه النظام)، تُعاد عند كل تركيز للنافذة
  وتُلغى في ملء الشاشة.
  (ب) **إلغاء انعكاس RTL**: الحافة اليسرى = رجوع واليمنى = تقدم دائمًا — سلوك
  كروم/سامسونج/إيدج الموحد؛ كان الانعكاس يجعل سحبة اليسار «تقدمًا» مع سجل
  تقدم فارغ فتبدو الإيماءة معطلة تمامًا.
  (ج) **إيماءة أسرع وأوضح**: منطقة التقاط أوسع (34dp بدل 26)، زناد أقرب
  (64dp بدل 84)، ونبضة لمس حسية عند الإطلاق.
- اختبارات جديدة تغطي السياسة الجديدة: intent بحزمة مجهولة (سيناريو Zen
  Player مع fallback المتجر)، المخطط الداخلي الوسائطي، وبقاء fail-closed
  لـ intent مجهول الوجهة تمامًا (بلا حزمة/وسائط/fallback مسموح).

  (هـ) **أولوية العارض**: `RENDERER_PRIORITY_IMPORTANT` أثناء الظهور —

- **صفحة البداية الافتراضية (إعادة تصميم كاملة)**: ترويسة هوية + شارة عدد
  المواقع + **شبكة بطاقات (3 أعمدة) بأيقونات المواقع الحقيقية (Favicons)**
  بدل الأزرار النصية — ضغطة تفتح عبر بوابة الأمان، وضغطة طويلة تعرض

- **قائمة المواقع المسموحة + سجل التصفح + بطاقات التبويبات**: كل صفوفها
  الآن تعرض أيقونة الموقع الحقيقية مع الحرف البديل خلفها حتى تنجح الصورة.
- **سجل التصفح — منع التكرارات على مستويين**: عند **التسجيل** نافذة دمج

  وتنقلات SPA، وعند **العرض** دمج التكرارات المتتالية في

  ملوّنة (مكتمل أخضر/فشل أحمر/انتظار كهرماني/جارٍ أزرق) ونسبة تقدم في

## 3. الضمانات الأمنية (ما لا يمكن كسره من الواجهة)

1. **القائمة البيضاء دائمًا:** `WhiteListEngine` بلا أي مفتاح إعداد لإيقافه؛
   `SecurityEngine` هو المنفذ الوحيد لكل تنقل (روابط/توجيهات/JS/popups/عناوين/سجل).
2. **الوصول المؤقت:** نافذة يفتحها الوالد بعد الرمز؛ انتهاؤها مخزن مشفرًا —
   إغلاق التطبيق لا يحولها لتجاوز دائم؛ حتى أثناءها تبقى المخططات الخطرة محظورة.
3. **السجل:** التسجيل بنيوي (لا مفتاح تعطيل)؛ المسح/الحذف داخل لوحة الوالدين فقط.
4. **التنزيلات:** كل تنزيل → `DownloadPolicy` (المصدر مسموح؟ المخطط ويب؟ النوع؟)
   — APK/EXE محظورة افتراضيًا، الأرشيفات والغير معروف ينتظر موافقة الوالدين.
5. **التطبيقات الخارجية:** إعداد والدين + كشف التثبيت + تأكيد صريح؛
   روابط التطبيقات (t.me/wa.me/youtu.be/Maps) إذا حظرتها القائمة → "فتح في التطبيق"
   بدل تجاوزها؛ `intent:` يُحكم على وجهته الاحتياطية عبر القائمة كاملة.
6. **التخزين:** PBKDF2-SHA256 للرمز (310k دورة)، AES-256-GCM بمفتاح Keystore لكل شيء حساس،
   بلا أسرار في الكود/السجلات/التفضيلات المكشوفة.

## 4. تدفقات المواصفة المطبقة

- **§7 إضافة موقع:** الوالدين → Add Website → Temporary Access → مدة → زيارة المواقع
  → History → "Add to WhiteList" → "ما الذي تريد السماح به؟" (3 خيارات) → حفظ → تنبيه
  "تمت الإضافة". انتهاء المؤقت = فرض تلقائي بلا تدخل.
- **§8 المؤشر:** شريط أصفر داخل المتصفح "وصول مؤقت — MM:SS" + إنهاء الآن؛
  التمديد من لوحة الوالدين فقط (إعادة مصادقة).
- **§30 الخطأ:** شاشة أصلية "تعذر تحميل الصفحة" + سبب مبسط + Retry/Back/Details
  (بلا رسائل WebView تقنية).
